# ADR 0006: Validate commands after shell expansion, snapshot before every write, allow-list on the resolved form

**Status:** accepted, 2026-09-02

## Context
Every major 2025–26 data-loss incident traced in doc 06 (A.1, A.3, C.3, D.2 item 1) had the same shape: the permission check saw the raw string and execution happened after expansion. claude-code #10077 (`rm -rf` expanded from `~/`), the Dec 2025 home-directory and Keychain wipe via a trailing `~/`, the Jul 2026 live Supabase reset through Prisma `--shadow-database-url`, the Antigravity `rmdir /s /q d:\` from an unquoted-space path, CVE-2026-25723 (piped-command bypass) and the 50-subcommand deny-rule truncation are all permission-layer bugs, not intent bugs. Users already run the fix as a PreToolUse hook (claude-code #28240, #16561). An LLM classifier alone is not enough: Anthropic's auto-mode classifier has a 17% false-negative rate on real over-eager actions and is intermittently unavailable (#91517, #91506). Undo that covers untracked and intra-turn changes is the top open ask in Codex (#9203, 464 reactions; #11626) and Claude Code's `/rewind` covers only its own edits (doc 07 §4 item 3).

## Decision
`saga guard` parses each proposed command with the target shell's grammar (bash, zsh, PowerShell, cmd), resolves tilde, variable, glob and quoting as that shell would, splits compound statements into segments, and classifies each segment on its resolved argv as read-only, mutating-in-scope, mutating-out-of-scope, or destructive. Policy is matched only on the resolved form. Unresolvable segments (`eval`, unknown expansions, dynamic `sh -c`) require confirmation. Hard denies on the resolved form cover recursive deletes at or above home, repo root or a drive root, destructive git, and framework data wipes, as a user-extensible list seeded from the incident ledger. Before any Bash, Write or Edit call, guard snapshots the working tree including untracked files (APFS or ZFS snapshot where available, content-addressed overlay otherwise) and `saga undo <turn>` restores it independently of the harness. Read-only segments and in-scope mutations declared in the gate contract run without a prompt; everything else asks. Guard is deterministic; a classifier may sit in front of it, never instead of it. Guard runs in front of an OS sandbox and never replaces one.

## Consequences
Fewer prompts and fewer bypasses at once, which no harness currently delivers. The unresolvable-command rate per shell is an open measurement (doc 09 §7 item 6) and, if high, reintroduces prompt fatigue. Snapshot cost on large working trees without a snapshotting filesystem is unmeasured (item 7). The incident fixture suite needs ongoing curation (item 11). Windows is a first-class target from M1 or guard becomes the next entry in doc 07 §6 item 14.
