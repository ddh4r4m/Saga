# ADR 0007: Per-turn cost ledger with cache accounting, version pinning, and canary evals

**Status:** accepted, 2026-09-02

## Context
Opaque cost is the top-ranked cross-harness problem in doc 07 §6: claude-code #16157 (724 reactions, 1,491 comments) found "accumulated tool output dragging hundreds of thousands of tokens on every single turn" only through a user's own 82-session analysis; #46829 (cache TTL silently regressed from 1h to 5m) was closed not_planned and later confirmed as two bugs; #46917 showed cache_creation inflated ~20K tokens per request server-side; codex #28879 reported per-token cost up 10–20× and was batch-closed without explanation. Model and harness regressions are indistinguishable to users (#42796, 3,286 reactions, traced to effort and thinking defaults; gemini-cli silent Pro→Flash, #2208, #28859; codex #30364 reasoning-token quantisation), and no project in the 32-repo set runs a public scheduled regression suite (doc 07 §6 item 8). Doc 07 §8 concludes the only externally available determinism levers are pinning, recording, verifying, and canary runs, and every one exists in the trackers as a user-built workaround. Doc 04 §5.8 notes nobody attributes cost to config components.

## Decision
`saga trace` records, for every model call, fresh input, cache-read, cache-write, output and reasoning tokens, the observed cache TTL, tool-output bytes added this turn, and the component responsible (index, mem, shape, harness prompt, user), sourced from the harness transcript where available and a local proxy capture otherwise. Budgets per session and per task warn, force compaction, or stop, with the decision logged. Every session records harness version, model id as returned by the API, effort or thinking setting, provider request ids and fingerprints, and the observed cache TTL; any change mid-session or between consecutive sessions is surfaced as an event, and a vendor fallback marks the run non-comparable in the bench. A fixed 10 to 20 task subset of `saga bench` runs on a schedule and on any detected version change, reporting pass^k, tokens per task and cache-hit ratio against the pinned baseline with a confidence bound derived from the 3.5 to 4.5 point per-model standard error (doc 06 A.10). The ledger is what makes any "token optimizer" claim a profiler reading rather than a README number.

## Consequences
The bench cannot ship without the ledger, so both land in M0. Canary statistical power at that standard error is an open question that sets its cadence and cost (doc 09 §7 item 8). Proxy capture is a privacy-sensitive path and must itself pass the guard layer. The ledger reveals Saga's own per-turn cost, which is the point: every layer's overhead is published alongside its effect.
