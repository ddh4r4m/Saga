# GitHub-issue mining: what coding-agent harnesses and agent tooling have solved, what they haven't, and why

Date: 2026-09-02. Raw pulls (top-30 open/closed by reactions and by comments for 32 repos, repo/release metadata, per-issue detail + last comments for ~45 key issues, theme counts) are in `scratchpad/issues-raw/` (`<owner>_<repo>.{open,closed}_{reactions,comments}.json`, `detail/`, `themes2.tsv`, `stats_table.md`).

## 0. Method and caveats

- Ranking used GitHub search `sort=reactions` (total reactions) and `sort=comments`, top 30 each, open and closed separately, per repo. `state_reason` (completed / not_planned / duplicate) plus the closing actor and last three comments were fetched for key issues to classify *how* they closed (fix, wontfix, stale-bot, duplicate).
- Theme counts are **title-only** keyword searches (`in:title`) because GitHub rejects >5 boolean operators and body search is dominated by mega-threads. Treat counts as relative signal, not census.
- Repo renames encountered: `sst/opencode` → **anomalyco/opencode**; `All-Hands-AI/OpenHands` → **OpenHands/OpenHands**; `block/goose` → **aaif-goose/goose**; `ruvnet/claude-flow` → **ruvnet/ruflo**; GSD is **gsd-build/get-shit-done**; caveman is **JuliusBrussee/caveman** (plus the unrelated **wilpel/caveman-compression**); ponytail is **DietrichGebert/ponytail**. `opencode-ai/opencode` is the abandoned original (last push 2025-09-18).
- `anthropics/claude-code` is issues-only (closed source): 14,309 open / 74,448 closed issues, the largest tracker in the set by far. `microsoft/vscode-copilot-chat` has only 15 issues total (issues live in `microsoft/vscode`), so it contributes little.
- Important bias: the *most-reacted* issues on the big harnesses are billing, account, and TUI issues (usage limits, phone verification, terminal flicker), not agent-behaviour issues. Agent-behaviour problems show up as thousands of medium-reaction issues, which is why the theme counts and the "closed by design change" analysis matter more than the raw top-15.

## 4. Long-lived open issues (>6 months, many reactions) and why they are hard

1. **Usage-limit / token-burn opacity** — claude-code [#16157](https://github.com/anthropics/claude-code/issues/16157) (724 r, 1,491 c, since 2026-01), [#38335](https://github.com/anthropics/claude-code/issues/38335), [#46917](https://github.com/anthropics/claude-code/issues/46917), [#13354](https://github.com/anthropics/claude-code/issues/13354) "Continue when the session limit reached" (210, since 2025-12); codex [#14593](https://github.com/openai/codex/issues/14593)/[#28879](https://github.com/openai/codex/issues/28879)/[#41220](https://github.com/openai/codex/issues/41220) meta-tracker. Hard because the cost function is server-side and opaque (cache TTL, cache-write inflation, model routing, "User-Agent routing" per #46917), and because the harness's own behaviour (accumulated tool output: "82 real sessions… accumulated tool output dragging hundreds of thousands of tokens on every single turn" in #16157) is invisible to the user. No harness exposes a per-turn cost ledger the user can act on.
2. **Terminal rendering** — claude-code [#826](https://github.com/anthropics/claude-code/issues/826) (822 r, since 2025-04), [#769](https://github.com/anthropics/claude-code/issues/769), [#1913](https://github.com/anthropics/claude-code/issues/1913), [#18170](https://github.com/anthropics/claude-code/issues/18170), [#1547](https://github.com/anthropics/claude-code/issues/1547) IME. Hard because Ink/React TUIs redraw the whole viewport; a 17-month-old bug. Not solvable externally except by using a different front-end.
3. **Undo / checkpointing that covers non-git state** — codex [#9203](https://github.com/openai/codex/issues/9203) (464) and [#11626](https://github.com/openai/codex/issues/11626) (212); kilocode [#8777](https://github.com/Kilo-Org/kilocode/issues/8777) "Revert and Checkpoints… not working"; cline [#4388](https://github.com/cline/cline/issues/4388) "Fix Checkpoint System Issues". Hard because a correct undo has to snapshot untracked files, intra-turn overwrites and *conversation state* together; Claude Code's /rewind does this only for its own edits.
4. **Compaction control** — codex [#4106](https://github.com/openai/codex/issues/4106) "Control over auto-compaction parameters" (119, since 2025-09); sdk [#23](https://github.com/anthropics/claude-agent-sdk-python/issues/23) and [#772](https://github.com/anthropics/claude-agent-sdk-python/issues/772); kilocode [#9494](https://github.com/Kilo-Org/kilocode/issues/9494). Hard because compaction is a lossy summarisation whose quality depends on the model, and no harness lets the user (or an external process) specify *what must survive*. The community answer was to build external state: #34556's author "built a complete memory persistence system from scratch because one didn't exist"; Cozempic (a pruning daemon) is advertised inside #7530.
5. **Instruction adherence (CLAUDE.md / GEMINI.md / AGENTS.md ignored)** — gemini-cli [#13852](https://github.com/google-gemini/gemini-cli/issues/13852) (P1, since 2025-11), claude-code [#77136](https://github.com/anthropics/claude-code/issues/77136) (541), [#60705](https://github.com/anthropics/claude-code/issues/60705), kilocode [#11967](https://github.com/Kilo-Org/kilocode/issues/11967) "Plan Agent behaves like Code Agent and ignores rules.md". Hard because it is a model property; the harness can only re-inject. Evidence that re-injection is not enough: caveman [#303](https://github.com/JuliusBrussee/caveman/issues/303) "drifts back to natural prose mid-session… despite SessionStart + UserPromptSubmit hooks firing every turn".
6. **Model fallback / silent model switching** — gemini-cli [#2208](https://github.com/google-gemini/gemini-cli/issues/2208) (not_planned), [#28859](https://github.com/google-gemini/gemini-cli/issues/28859); claude-code [#91522](https://github.com/anthropics/claude-code/issues/91522) "Unintended model switching to Opus", [#91369](https://github.com/anthropics/claude-code/issues/91369) "silently downgraded… mid-session"; Roo [#12237](https://github.com/RooCodeInc/Roo-Code/issues/12237) "Selected model should never change unless the end-user changes it"; opencode [#7602](https://github.com/anomalyco/opencode/issues/7602). Hard because vendors *want* routing freedom under capacity pressure; the user wants determinism.
7. **Edit-tool reliability** — cline [#4384](https://github.com/cline/cline/issues/4384) (14 months), gemini-cli [#1028](https://github.com/google-gemini/gemini-cli/issues/1028), serena [#576](https://github.com/oraios/serena/issues/576) "replace_symbol_body seems to cause duplicate code often", OpenHands [#8958](https://github.com/OpenHands/OpenHands/issues/8958). Hard because the failure is a joint property of model (exact-string reproduction, escaped newlines) and tool (whitespace normalisation, CRLF, fuzzy matching thresholds); every harness re-implements it.
8. **Multi-agent orchestration parity** — opencode [#12661](https://github.com/anomalyco/opencode/issues/12661) and [#5887](https://github.com/anomalyco/opencode/issues/5887) (both stale-closed), Roo [#12330](https://github.com/RooCodeInc/Roo-Code/issues/12330), gemini-cli [#19430](https://github.com/google-gemini/gemini-cli/issues/19430), superpowers [#429](https://github.com/obra/superpowers/issues/429) (113, top open). Hard because it needs a scheduler, shared state, and audit trail; Codex's attempt regressed observability ([#28058](https://github.com/openai/codex/issues/28058)) and Claude Code's has races ([#91513](https://github.com/anthropics/claude-code/issues/91513) "`git commit --amend`… can silently rewrite a concurrent teammate's commit").
9. **Sandboxing** — opencode [#2242](https://github.com/anomalyco/opencode/issues/2242) (open 13 months); claude-code [#91512](https://github.com/anthropics/claude-code/issues/91512) "Sandboxed Bash leaves… tmp directories… fills disk at several GB/hour"; copilot-chat [#5098](https://github.com/microsoft/vscode-copilot-chat/issues/5098) "Sandbox settings file is writable by sandboxed process, allowing self-modification of restrictions"; codex [#2847](https://github.com/openai/codex/issues/2847) secrets exclusion "doesn't yet enforce consistently across surfaces". Hard because OS sandboxes (seatbelt/landlock/bwrap) are platform-specific and leak through network, temp dirs and the config file itself.
10. **Standards adoption lag** — AGENTS.md took Anthropic 12 months ([#6235](https://github.com/anthropics/claude-code/issues/6235)); Aider never added MCP ([#3314](https://github.com/Aider-AI/aider/issues/3314)); ACP was declined ([#6686](https://github.com/anthropics/claude-code/issues/6686), 552 r, not_planned); XDG ignored by both Claude Code ([#1455](https://github.com/anthropics/claude-code/issues/1455)) and Codex ([#1980](https://github.com/openai/codex/issues/1980)). Hard for incentive reasons (lock-in: "This is very likely a case of deliberate vendor lock-in" in #31005), not technical ones.

## 6. The 20 most painful cross-harness problems (ranked)

Ranking weights reactions, comment volume, number of harnesses affected, and persistence.

1. **Opaque cost / quota burn.** claude-code #16157 (724/1,491c), #38335, #46829, #46917, #9424 "Weekly Usage Limits Making Claude Subscriptions Unusable"; codex #14593 (630c), #28879, #30364, #41220; opencode #7410, #16017 usage API; gemini #24937. *Solved?* No. Codex batch-closed its cluster on 2026-08-23 without explanation. *External layer:* yes, partially — a proxy or transcript-JSONL analyser can produce a per-turn ledger (fresh vs cached input, tool-output bytes per turn) and enforce budgets (kill or compact at N tokens). Users already built these (CODEX-Inspection-Guidelines-for-Dosage, ccusage-type tools, #16157's 82-session analysis).
2. **Context loss on compaction and no control over what survives.** claude-code #7530, #5385, #18866 "Auto-compact not triggering…", #34556, #24055 "response exceeded the 32000 output token maximum"; codex #4106; sdk #23/#772; kilocode #9494; goose #11318; letta [#3270](https://github.com/letta-ai/letta/issues/3270) "sliding_window compaction ignores percentage, performs full context wipe". *Solved?* Partially: Claude Code added `PreCompact` hook and auto-memory; nobody lets you declare invariants. *External:* yes — a PreCompact/SessionStart hook pair that writes a structured state file (goals, decisions, file list, test status) and re-injects it is harness-agnostic given hook parity (Claude Code, Codex, Gemini all have hooks now).
3. **Instruction files ignored / drift.** claude-code #6235, #31005, #77136, #60705; gemini #13852, #18186; kilocode #11967; caveman #303/#812; ponytail [#737](https://github.com/DietrichGebert/ponytail/issues/737) "Annoyance: Contrastive language"; mattpocock [#240](https://github.com/mattpocock/skills/issues/240) "GPT 5.5 often jumps straight to implementation after /grill-me". *Solved?* No. *External:* only by **verification, not exhortation** — a PostToolUse/Stop hook that checks outputs against machine-checkable rules (lint, forbidden paths, required test run) and rejects the turn. #77136's last comment reports rewriting the standing file "as a description of who the agent is rather than a list of orders" helped; anecdotal.
4. **Edit-tool failures and false success.** cline #4384/#2175/#7262; gemini #1028, #2553 "WriteFile will generate '�' character"; serena #576, [#1744](https://github.com/oraios/serena/issues/1744) "rename_symbol silently omits edits in files that are not open"; OpenHands #8958; Roo #11071 repeated file reads. *Solved?* Claude Code's Edit (exact old_string + preview) is most robust; Codex's apply_patch is second. *External:* yes for *detection* — diff the working tree after each turn and compare with the agent's claim ("agent claimed success with zero edits" tool in cline #4384). Fixing the tool itself requires the harness.
5. **Permission fatigue and permission bypass.** claude-code #28240 (cd-prefix prompts; allow-list workaround "does not suppress this prompt", only a PreToolUse hook does), #91517 "Auto-mode safety classifier intermittently unavailable", #91506 "Auto mode ran a destructive GitHub ProjectV2 mutation unflagged — wiped 12 completed sprints; classifier then blocked the identical restore call"; kilocode #10068 agent executes denied operations; codex #2847; goose #11399 regex allow/ask/deny; Roo [#5502](https://github.com/RooCodeInc/Roo-Code/issues/5502) "Auto-approve does not apply, sometimes". *Solved?* No harness has a permission model users trust at both ends (too many prompts *and* bypasses). *External:* yes — PreToolUse hook with a deterministic command classifier (read-only vs mutating, per-segment for `&&` chains) is exactly what #28240's community workaround is; it's portable across hook-bearing harnesses.
6. **Destructive actions / data loss.** gemini #26856 (10,000s of Obsidian files deleted, stale-closed); claude-code #91506, #91513, #4928 "file named nul created on windows" (235 r); codex #9203 (undo removed). *Solved?* Checkpoints (Claude /rewind) only cover agent edits. *External:* yes — filesystem snapshot per turn (git stash-like overlay, or ZFS/APFS snapshot) before any Bash/Write, independent of harness.
7. **Hangs, stalls and silent failures.** claude-code #26224 "[URGENT!!!] hanging / freezing / stuck… 5-20 minutes" (151 r), #46987 "Stream idle timeout" (197), #91502 "connections go silent; client waits 180s+", #91503 subagent notification with no idle-wake consumer; gemini #22141 (stale-closed at 219 comments); cline #4356 (8 stall patterns), #1157; goose #11164. *External:* partial — an outer watchdog (no tool call or token for N seconds ⇒ kill/resume) is trivially harness-agnostic; the memory-alive-file pattern this very research used is the same idea.
8. **Model-quality regressions indistinguishable from harness regressions.** claude-code #42796 (3,286 r), #77136, #91516 "Model switching… degrades output quality"; codex #30364 reasoning clustering, [#29353](https://github.com/openai/codex/issues/29353); gemini #2208/#28859 silent fallback; ponytail [#126](https://github.com/DietrichGebert/ponytail/issues/126) "Benchmark issues - baseline scores are ~7 times better". *External:* yes for detection — a fixed regression suite run on a schedule against the harness (the "canary") would have surfaced #42796 before 583 comments did; nobody in the set does this publicly (gemini [#23331](https://github.com/google-gemini/gemini-cli/issues/23331) "GSoC Behavioral evals" is a proposal).
9. **Looping / repeated tool calls.** claude-code (892 open loop-titled issues by body search), sdk #775; Roo #11071, #10322 "OpenAI Compatible mode loops when model responds without tool call"; kilocode [#4358](https://github.com/Kilo-Org/kilocode/issues/4358) "Opus 4.5 infinite loop"; OpenHands #7183 (solved with detector). *External:* yes — repeated-identical-call detector in a PostToolUse hook, plus a turn cap.
10. **The "60-second auto-answer" anti-pattern.** claude-code #73125 (fixed), codex #28969 (open), GSD #803/#912 (blamed upstream). *External:* no — it's harness UI; but an external layer must *never* replicate it.
11. **Memory across sessions.** claude-code #34556, #2511 "Connect Claude code to Claude projects" (620 r, since 2025-06); opencode [#8751](https://github.com/anomalyco/opencode/issues/8751); mem0 [#5245](https://github.com/mem0ai/mem0/issues/5245) "Silent memory loss when batch embedding partially fails", [#4956](https://github.com/mem0ai/mem0/issues/4956) "ADD-only extraction… stale/contradictory facts"; letta [#3388](https://github.com/letta-ai/letta/issues/3388) "Cross-Session State Leakage via Persistent Core Memory Poisoning"; MCP memory server [#1018](https://github.com/modelcontextprotocol/servers/issues/1018)/[#692](https://github.com/modelcontextprotocol/servers/issues/692) ignore storage path. *Solved?* Every memory product has its own silent-loss and poisoning bugs. *External:* yes, and the safest form is plain files in the repo (what #34556 and Claude Code's auto-memory converged on), not a vector DB.
12. **MCP: bloat, breakage, security.** claude-code #6915/#4476/#7328 (solved by scoping), #1785 sampling; servers [#64](https://github.com/modelcontextprotocol/servers/issues/64) "MCP Servers Don't Work with NVM" (182 r), [#3537](https://github.com/modelcontextprotocol/servers/issues/3537) "Security Audit: Unconstrained string parameters across all official servers", [#754](https://github.com/modelcontextprotocol/servers/issues/754) credential management (not_planned), [#4117](https://github.com/modelcontextprotocol/servers/issues/4117) memory server safer persistence; ruflo [#1375](https://github.com/ruvnet/ruflo/issues/1375) "Prompt Injection via MCP Tool Descriptions… hidden instructions that direct the LLM to add the repository owner"; serena [#494](https://github.com/oraios/serena/issues/494) "Failed to connect in Claude code" (43 c). *External:* yes — an MCP gateway that lazy-loads schemas, strips/scans tool descriptions for injected instructions, and logs calls.
13. **Multi-agent coordination without audit trail.** codex #28058, #31814 "cannot specify subagent models"; claude-code #91513, #91503; opencode #12661/#5887 (stale); superpowers #429; Roo #12330. *External:* partially — orchestration can live outside (repowire, claude-flow tried), but shared-worktree correctness needs harness cooperation.
14. **Windows / WSL / path issues.** claude-code #4928 (nul file), #91523 orphaned find.exe, #91500 WSL symlinks, #1232 JetBrains on WSL; kilocode #9440 PowerShell vs Bash; caveman [#366](https://github.com/JuliusBrussee/caveman/issues/366) PowerShell installer; unlazy [#30](https://github.com/Leonxlnx/unlazy/issues/30) "Every file read fails closed on Windows"; ruflo [#615](https://github.com/ruvnet/ruflo/issues/615); mem0 [#2690](https://github.com/mem0ai/mem0/issues/2690) CRLF; servers [#470](https://github.com/modelcontextprotocol/servers/issues/470). *External:* an external layer must be tested on Windows or it will be the next entry in this list.
15. **Local / OpenAI-compatible model tool-calling.** cline #7262, #1418, #5915; Roo #10322, #11071, #4047 RFC; kilocode [#3967](https://github.com/Kilo-Org/kilocode/issues/3967), #11437; goose [#10012](https://github.com/aaif-goose/goose/issues/10012). Harnesses tune prompts for frontier models; weaker models loop on tool syntax. *External:* a normalising proxy (fixed chat templates, tool-call repair) — several exist.
16. **Model/provider lock-in of subscriptions.** claude-code #17118 (1,416 r), Roo #10566 "This credential is only authorized for use with Claude Code", kilocode #5460 "Gemini CLI removed", opencode #7410. Not technical; unsolvable externally without ToS risk.
17. **Sandbox correctness.** opencode #2242; claude-code #91512; copilot-chat #5097/#5098/#5099; codex #2847. *External:* container-level sandbox (Docker/devcontainer) is the only portable answer; OpenHands does this by default ([#8555](https://github.com/OpenHands/OpenHands/issues/8555) "Slow docker sandbox startup" is the cost).
18. **Skill/plugin discovery and triggering unreliability.** anthropics/skills [#556](https://github.com/anthropics/skills/issues/556) "claude -p never triggers skills/commands (0% trigger rate)" — "four independent causes, and each one alone produces ~0% recall"; mattpocock [#908](https://github.com/mattpocock/skills/issues/908) "Six skills are silently unreachable through the CLI: unquoted `: ` in description frontmatter"; vercel-labs/skills [#693](https://github.com/vercel-labs/skills/issues/693) "Claude Code cannot read globally installed skills from ~/.agents/skills", [#1138](https://github.com/vercel-labs/skills/issues/1138) "silently skips Claude Code symlinks"; BMAD [#1956](https://github.com/bmad-code-org/BMAD-METHOD/issues/1956) "opencode does not load any skills involving a workflow.md". Skills are files whose *loading* fails silently. *External:* yes — a `skill-doctor`-style validator and an install-time smoke test.
19. **Terminal/TUI usability** (claude-code #826/#769/#1913/#18170; opencode #4283 clipboard, #1505 shift+enter; kilocode #3679). Not externally solvable; noted because it consumes a large share of reactions.
20. **Triage itself.** claude-code #16497 (238 r) and #87647; gemini #22141/#26856 stale-closed at 219 and 49 comments; opencode #12661/#5887 stale-closed; #60705 "Auto-closure overrides human triage". Users cannot tell whether a problem is known, fixed, or wontfix; an external layer that maintains a curated "known failure modes + mitigations" registry has value precisely because the trackers are unusable at this scale.

## 7. Mistakes to avoid — evidence from the tooling repos' own trackers

- **Token bloat from always-on instructions.** superpowers [#743](https://github.com/obra/superpowers/issues/743) "Im seeing slowness in responses since using the skill" (32 r, top open by comments), [#512](https://github.com/obra/superpowers/issues/512) "brainstorming/writing-plans SKILL efficiency"; spec-kit [#1401](https://github.com/github/spec-kit/issues/1401) "Spec-kit commands consume significant portion of context window in every session"; anthropics/skills #1486; ponytail [#597](https://github.com/DietrichGebert/ponytail/issues/597) "SubagentStart always sends the full SKILL.md" and [#502](https://github.com/DietrichGebert/ponytail/issues/502) "SubagentStart hook injects lazy-mode into every subagent, including code reviewers"; caveman [#374](https://github.com/JuliusBrussee/caveman/issues/374) "Make bundled skills/agents/commands opt-in". Lesson: everything injected on every turn is paid on every turn; make injection conditional and measured.
- **Over-specification / process rigidity.** superpowers [#895](https://github.com/obra/superpowers/issues/895) "writing-plans: plans over-specify implementation, leaving no room for executor judgment" (35 r), [#1120](https://github.com/obra/superpowers/issues/1120) "subagent driven development could skip reviews for 'easy' tasks", [#4](https://github.com/obra/superpowers/issues/4) "Option/config to disable git workflow" (not_planned); mattpocock [#44](https://github.com/mattpocock/skills/issues/44) "Codex just asked me 200 questions" (not_planned), [#508](https://github.com/mattpocock/skills/issues/508) "/implement has no completion step, finished tickets are never marked done"; spec-kit [#1191](https://github.com/github/spec-kit/issues/1191) "Can't Easily Update or Refine Existing Specs" (115 r, its top issue), [#620](https://github.com/github/spec-kit/issues/620) "How to keep specs consistent and up-to-date". Lesson: workflows that cannot be partially applied get abandoned; the top spec-kit complaint is *editing* specs, not creating them.
- **Model-specific breakage.** superpowers [#2017](https://github.com/obra/superpowers/issues/2017) "Retuning subagent driven development for Opus 6 and Sol 5.6"; mattpocock #240 (GPT-5.5 skips the grill step); ponytail [#65](https://github.com/DietrichGebert/ponytail/issues/65) "Impact on model performance?" closed *completed* without a benchmark ("not sure why this was closed… still not properly benchmarked?") and #126 baseline 7× off; caveman #303/#812 drift. Lesson: prompt-only tooling has no regression suite, so every model release silently changes its behaviour.
- **Harness-specific breakage multiplied by N harnesses.** caveman: [#373](https://github.com/JuliusBrussee/caveman/issues/373) Gemini "Invalid tool name", [#325](https://github.com/JuliusBrussee/caveman/issues/325) Gemini extension fails (not_planned), [#367](https://github.com/JuliusBrussee/caveman/issues/367) OpenCode install fails, [#366](https://github.com/JuliusBrussee/caveman/issues/366) PowerShell; ponytail [#582](https://github.com/DietrichGebert/ponytail/issues/582) Cowork marketplace, [#708](https://github.com/DietrichGebert/ponytail/issues/708) "Hook error on missing Node", [#573](https://github.com/DietrichGebert/ponytail/issues/573) "Codex hooks fail JSON validation", [#759](https://github.com/DietrichGebert/ponytail/issues/759) Copilot `${PLUGIN_ROOT}`; superpowers [#792](https://github.com/obra/superpowers/issues/792) "Copilot CLI: no way to inject superpowers bootstrap at startup"; vercel-labs/skills [#403](https://github.com/vercel-labs/skills/issues/403) copilot folder location; BMAD #1956. Lesson: each harness has a different plugin manifest, hook JSON schema, skills dir, and shell; a "harness-agnostic" layer that ships N adapters inherits N×bugs unless the core is a plain executable with a thin adapter per harness.
- **Silent failures.** mattpocock #908 (six skills unreachable, closed not_planned), anthropics/skills #556 (0 % recall, and the optimiser "improves" against a constant-zero signal), vercel-labs/skills #1138, BMAD [#2616](https://github.com/bmad-code-org/BMAD-METHOD/issues/2616) "intermittently omits the '## Auto Run Result' append", [#2772](https://github.com/bmad-code-org/BMAD-METHOD/issues/2772) "follow-up-review flag cannot return false", unlazy UL001–UL003 ("abandoned required gates can still receive `ALL MET`", "a multi-deliverable PLAN can omit required work while every declared gate passes", "A gate can pass when its CHECK never observes the thing the gate is about"). Lesson: a verification layer needs to verify *itself* — gates must fail closed and be testable with a fixture that should fail.
- **Security debt in agent tooling.** ruflo #1375 (prompt injection in tool descriptions, obfuscated preinstall script; corroborated by a second audit in April), [#442](https://github.com/ruvnet/ruflo/issues/442) "SQLite Storage Always Falls Back to In-Memory Due to Logic Error"; vercel-labs/skills [#523](https://github.com/vercel-labs/skills/issues/523) "Invasive credential retrieval: 'skills add' invokes 'gh auth token'"; anthropics/skills [#492](https://github.com/anthropics/skills/issues/492) "Community skills distributed under anthropic/ namespace enable trust boundary abuse" (43 c); ponytail [#735](https://github.com/DietrichGebert/ponytail/issues/735) trojanised clone; BMAD [#2625](https://github.com/bmad-code-org/BMAD-METHOD/issues/2625) "brain.py resolve_detail() reads arbitrary local files", [#2624](https://github.com/bmad-code-org/BMAD-METHOD/issues/2624) "skills execute {project-root}/_bmad/scripts/*.py". ## 8. Run-to-run inconsistency and "it worked yesterday"

The trackers are saturated with temporal regressions that users cannot attribute:
- Title-level examples: claude-code [#20571](https://github.com/anthropics/claude-code/issues/20571) "Tool use concurrency error after Jan 23-24 update", [#38335](https://github.com/anthropics/claude-code/issues/38335) "since March 23, 2026", [#41930](https://github.com/anthropics/claude-code/issues/41930) "abnormal usage limit drain across all paid tiers since March 23, 2026", [#46829](https://github.com/anthropics/claude-code/issues/46829) "silently regressed… around early March 2026", [#46917](https://github.com/anthropics/claude-code/issues/46917) "v2.1.100+ inflates cache_creation… vs v2.1.98", [#9094](https://github.com/anthropics/claude-code/issues/9094) "Unexpected change in Claude usage limits as of 2025-09-29 (30+ reports)", [#40524](https://github.com/anthropics/claude-code/issues/40524) "Conversation history invalidated on subsequent turns", [#91514](https://github.com/anthropics/claude-code/issues/91514) "Warm prompt cache fully re-written… seconds after ToolSearch / Skill / tool_result on v2.1.258"; codex [#28879](https://github.com/openai/codex/issues/28879) "since June 16", [#14593](https://github.com/openai/codex/issues/14593) "following today's extension update"; gemini [#22141](https://github.com/google-gemini/gemini-cli/issues/22141), [#28859](https://github.com/google-gemini/gemini-cli/issues/28859); kilocode [#8108](https://github.com/Kilo-Org/kilocode/issues/8108)/[#8364](https://github.com/Kilo-Org/kilocode/issues/8364); Roo [#5502](https://github.com/RooCodeInc/Roo-Code/issues/5502) "Auto-approve does not apply, sometimes"; GSD [#803](https://github.com/gsd-build/get-shit-done/issues/803) "Since the update 1.21.1 -> 1.22.0"; caveman #303 (works for 3–5 turns then drifts).
- Structural causes visible in the data: (1) **server-side changes with no client version bump** — cache TTL (#46829), cache-write inflation keyed on User-Agent (#46917), model routing/fallback (#2208, #28859, #91522/#91369), reasoning-budget quantisation (#30364); (2) **daily harness releases** (Claude Code ~daily, Gemini nightlies, cline 100 releases/90 days, ruflo 100/90 days) with prompt/tool-description changes that are not in changelogs — the April post-mortem for #42796 attributed the regression partly to harness-side changes; (3) **stochastic instruction adherence** — #13852 and #303 both describe rules that hold "most of the time", which is why users experience the same prompt succeeding one day and failing the next; (4) **auto-mode/classifier availability** — #91517 "safety classifier intermittently unavailable" makes permission behaviour itself non-deterministic; (5) **cache-state dependence** — #38335's thread discovers that a session idle past the cache TTL costs a full re-write on the next turn ("one message ate my whole window"), so *timing* changes cost and, via context, behaviour.
- What users do about it: pin versions (users in #14593 downgrade; codex-pooler; "find-and-replace every update" for #28969), build monitors (tylerchen0123-sudo's token monitor; #46917's proxy capture; the 82-session and 66-session analyses in #16157/#4389), and maintain parallel instruction files (#31005). None of these is provided by a harness.
- Implication: the only externally-available determinism levers are **pinning** (harness version, model id, no auto-routing where possible), **recording** (full request/response capture via proxy or transcript JSONL, per-turn token ledger), **verifying** (post-turn checks that do not depend on the model's self-report), and **canary regression runs** that detect "it changed" before the user does. Every one of these appears in the trackers as a user-built workaround, and none appears as a shipped harness feature across more than one harness.

## 9. What an external, harness-agnostic layer can and cannot do (summary)

Can (with high confidence, because users already did it ad hoc): per-turn cost ledger and budget enforcement; state file re-injection around compaction (PreCompact/SessionStart); deterministic command classification in PreToolUse; filesystem snapshot per turn; loop/stall watchdog; post-turn verification of claims (diff exists, tests actually ran, forbidden paths untouched); MCP gateway with lazy schemas and description scanning; skill/plugin load-time validation; version pinning + canary evals. The hook surface (PreToolUse/PostToolUse/Stop/SessionStart/PreCompact) now exists in Claude Code, Codex and Gemini CLI and is deliberately compatible ([gemini-cli #2779](https://github.com/google-gemini/gemini-cli/issues/2779)), which is the seam.

Cannot: fix the edit tool, terminal rendering, sandbox leaks, model fallback, subscription lock-in, or the 60-second auto-answer; cannot make a model obey a prose rule — only reject its output.

Design constraints learned from the tooling trackers: inject nothing unconditionally; fail closed and test the gates against a known-bad fixture; ship as one executable with thin per-harness adapters; test on Windows; no SessionStart code paths that execute repo-supplied scripts; provide `uninstall`; version the prompts and publish a benchmark delta per model release.
