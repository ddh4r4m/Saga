# `saga gate` implementation review

*2026-09-03. Security and correctness review of commit cca728e (`internal/gate`, `internal/snapshot`, the gate step in `internal/hook`, `schema/gate/1`) against gate-spec v0.3, `00-cross-spec-contracts.md` v0.2, `harness-probes.md` and the two interpretations recorded in `IMPLEMENTATION-STATUS.md`. Method: read every file, replay the recorded Claude Code hook payloads (`hookprobe/log/p1b..p7`), run adversarial contracts and Bash strings through the built binary, and measure on a synthetic 20,003-file tree. Every finding marked fixed has a test in `internal/gate/review_test.go` or `internal/snapshot/snapshot_test.go`. No em-dashes.*

## 2. Spec interpretations

| Interpretation (IMPLEMENTATION-STATUS) | Verdict | Reasoning |
|---|---|---|
| `REQUEST:` is the sha256 of the verbatim `.saga/request.md`; the SEGMENTER v1 numbering is derived on every read, not stored. | **Accepted** | The hash then names the request itself, which is what the bench hashes (`prompt.md`), and row 11 (quote must occur in the named sentence) catches a renumbering whenever the quote no longer lands. Condition: pin the segmenter version in the record (`segmenter: v1` on the status report or in `request_hash`'s domain) before a v2 exists, otherwise a v2 renumbering that happens to keep a quote inside the new sentence would pass silently. |
| Default witnesses: a `CHECK:` token naming an existing file is a witness unless it matches an `IN:` glob (the subject of the work); explicit `WITNESS:` always binds. | **Accepted with a documented hole** | The literal reading (every token binds) makes `ts-0004` G1 (`node scripts/build.mjs`, `scripts/**` in `IN:`) and the grep-style regression gates (`ts-0001` G3, `ts-0002` G1, `py-0009` G2) unprovable: the first in-scope edit voids the baseline red and no second baseline can be taken. The hole: an agent that authors `IN:` to cover the oracle script can rewrite the script after approval and red proof (`console.log('passed')`) without re-approval. Remedies already in the design: a `BASE:`-committed contract (G-LEDGER `header-changed` once evidence exists), explicit `WITNESS:` lines for oracle scripts and fixtures, CI `reverify`. Recommended spec text for section 3.4: "a default witness matched by `IN:` is the subject, not an input; list oracle scripts under `WITNESS:` explicitly". Recommended bench rule: task contracts name their oracle scripts in `WITNESS:`. |

## 3. Performance

Synthetic tree of 20,003 tracked files (200 packages, 100 modules each), Apple silicon, macOS, machine shared with two other agents' test runs; 10 runs each, Python `subprocess` overhead included. `git status --porcelain` is the reference cost of one working-tree scan on this filesystem.

| Step | Before | After index seeding | After diff memo |
|---|---|---|---|
| `git status --porcelain` (reference) | 594 ms p50 | 497 ms | 499 ms |
| `saga gate status` (clean) | 4,344 ms p50, 5,081 p95, 10,750 max | 1,300 ms p50, 1,325 p95 | 1,253 ms p50, 1,283 p95 |
| Stop hook (`status` plus write-tree) | 4,313 ms p50, 4,448 p95 | 1,330 ms p50, 1,409 p95 | 1,264 ms p50, 1,280 p95 |
| Stop hook (dirty: 1 modified, 1 untracked) | 4,370 ms p50 | 1,333 ms p50 | 1,363 ms p50 |
| PostToolUse Bash (guard-diff) | 591 ms p50 | 622 ms p50 | 601 ms p50 |
| PreToolUse Bash (string match only) | 7.4 ms p50 | 8.3 ms | 8.1 ms |
| Small repository (3 files), Stop hook | 167 ms p50, 522 p95 | 155 ms p50, 190 p95 | |

Where the time goes: the temporary index was seeded with `read-tree HEAD`, which has no stat cache, so `git add -A` re-hashed all 20k files (about 3 s). Seeding from a copy of the real index re-hashes only stat-changed files. The remaining 1.25 s is two more working-tree scans (`git diff --name-status` and `ls-files -o` in guard-diff, about 600 ms together) plus the seeded `add -A` (about 500 ms) and roughly fifteen small git spawns. The per-gate `DiffEmpty` scan is gone (memoised on `Loaded`), which shows up as the flat PostToolUse figure rather than the Stop figure because the perf contract has one gate.

Next step if the 5 s deadline is ever approached again: one scan. After the seeded `add -A`, `git diff-index --cached --find-renames --name-status <BASE>` against the temporary index yields the same entries guard-diff needs without touching the working tree, so status would cost one scan (about the reference `git status`) instead of three. Also `core.untrackedCache` and `core.fsmonitor` in the user's git config cut the reference itself.

The contracts section 1.1 target (p95 300 ms with a snapshot) is not met on 20k files without that change; it is met on the small repository.
