One malformed event in the queue stops the whole webhook batch in src/dispatch.ts, and support then has to edit the queue by hand and rerun. A bad event must not stop the batch: the good events still reach the transport in queue order, and every bad event is reported in the result's failed list with the event's id, its position in the batch (the first event is position 1) and the reason from the renderer, so support can fix the events named. A failure from the transport itself is not a bad event and must still stop the dispatch as it does today. The new case in test/dispatch.test.ts fails.
