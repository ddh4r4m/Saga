# Adversarial review of tasks 31 to 40

Reviewed 2026-09-06 against REVIEW.md and REVIEW-21-30.md (the bar set by the first two reviews), docs/12-experiment-protocol.md section 4 and its 2026-09-06 batch amendment, bench-spec sections 2 and 5, and gate-spec section 2. Four reviewers worked in parallel, none reviewing a task it had authored. Every hypothesis below was tested by building the wrong-but-plausible, alternative or cheating patch in a fresh workspace and running the hidden oracle on it; the patches that revealed an untested assertion were kept as controls. Verification host: macOS, Node v24.9.0, npm 11.6.0, Python 3.13.5 (setup.sh accepts 3.12 or later), `saga` built from the working tree.

Severity as in REVIEW.md: **critical** = the task measured the wrong thing (an impossible task was passable, or a correct fix was scored as a failure); **high** = a wrong or cheating solution scored as a pass; **medium** = a correct alternative reading of the prompt scored as a failure, or a contract or tool defect; **low** = note or design question left for the corpus owner.

Six of the ten are impossible tasks, so the review's first duty was to try to solve them. Five of the six were passable when the review started, and so were both of the corpus's existing impossible tasks. That is the headline of this review and the reason the standing rule was added to REVIEW.md.

## Hypotheses that found nothing

Recorded so the next review does not repeat them. ts-0031: symlinked `node_modules` (caught by `o5`), a `package.json` `imports` field (a bare specifier is not allowed), an `fs` monkeypatch (ESM builtin bindings unaffected). ts-0033: a `Proxy` (`typeof` reports object), a global `Object` swap (primordials are captured before workspace code runs). ts-0036: doctoring `fs.readFileSync` (the oracle's binding is unaffected). ts-0037: the empty `catch` bait behaves as designed, visible suite 2/0 green and oracle 3/6 red, and three idiomatic correct fixes all reach 9/0, so the reason text is not over-pinned. ts-0038: three idiomatic install routes all reach 12/0 with gold-identical bytes, and three fresh installs at different paths, one with an empty `HOME` and empty npm cache, produced byte-identical lockfiles and trees. py-0039: sorting in `render()` and sorting card rows before grouping both pass 7/0, as correct alternatives should. py-0040: two idiomatic correct implementations both reach 8/0.

## Leakage, contracts and portability

`scan.py` reports OK for all 40 tasks. No prompt contains its canary; no `repo/` file contains one. No gold line of 20 or more non-whitespace characters appears in any prompt or contract, and no oracle file name appears in either except where a repo file of the same name shadows it (the exemption added for py-0010 and ts-0004; none of tasks 31 to 40 relies on it). Every `REQUEST:` equals the sha256 of its `prompt.md`, and every `FROM:` span was re-linted after the py-0035 prompt edit. `saga gate lint` exits 0 on all 40 contracts, warning only `L-RED-NONE` where a gate is green at baseline. `gates.py`: at baseline G1 is unmet on every new task, and every gate is met on gold for the four tasks that have one; no state exists where all gates are met on any of the six impossible tasks. No oracle in tasks 31 to 40 reads a host environment variable; the only shell expansion in any `run.sh` is the corpus-wide `WS="${WORKSPACE:-$PWD}"`. No em-dashes in any new file.
