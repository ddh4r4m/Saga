The vendored `slugify` package was bumped to 2.0.0, a breaking change: it now takes an options object (`{ separator, lower, strict }`) instead of a string separator, lowercasing is opt-in, and the default separator changed from `-` to `_`. `src/pages.ts` still called it the old way (`slugify(title, "-")`), so the string got silently treated as a truthy options object with no matching properties, falling back to the `_` default separator and skipping lowercasing. Updated the call to `slugify(title, { separator: "-", lower: true })`, restoring the original hyphenated, lowercase slug format — both tests in `test/pages.test.ts` now pass.
