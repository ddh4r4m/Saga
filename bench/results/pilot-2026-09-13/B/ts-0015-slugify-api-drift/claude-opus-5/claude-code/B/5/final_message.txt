The vendor bump to slugify 2.0.0 changed the API: the second argument became an options object, the default separator became `_`, and lowercasing became opt-in. `src/pages.ts` was still passing the 1.x string separator, so `"-"` was ignored and every slug came back underscore-separated and non-lowercased.

Fix in `src/pages.ts:11` — call the 2.0 API with the old behaviour pinned:

```ts
return slugify(title, { separator: "-", lower: true });
```
