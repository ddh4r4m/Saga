The slug regression came from the vendor bump, not from anything in `src`. slugify 2.0.0 changed its signature from `slugify(text, separator)` to `slugify(text, options)`, so the existing `slugify(title, "-")` call passed a string where an object was expected: the separator fell back to the new `_` default and lowercasing, which 1.x did unconditionally, became opt-in.

The fix is one line in `src/pages.ts:11`, adapting the call to the 2.0 API:

```ts
return slugify(title, { separator: "-", lower: true });
```

I left `vendor/slugify/index.ts` untouched — `vendor/README.md` says vendored files are exact upstream copies and must never be patched in place, since the next re-vendor would silently drop the patch.
