**What changed**

`overlaps/core.py:20` — the 0.4.1 rewrite compared all n²/2 pairs. The new version groups bookings by room, sorts each room's bookings by start, and sweeps with a min-heap keyed on end. At each step it pops heap entries that have already finished by the current booking's start time; whatever remains is still running, so every remaining entry is a candidate clash. The cost is O(n log n) plus one overlap check per reported clash, not per pair. Grouping by room is only a cheap partition — as docs/perf.md notes, it doesn't carry the scaling; the sweep does.

Notes on exactness: the per-candidate overlap check is kept rather than assumed, because a booking whose end precedes its start can sit on the heap without genuinely clashing. I confirmed that check can only filter false positives and never drops a pair the old code found, including that reversed/empty-interval case.
