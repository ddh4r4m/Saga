**Cause:** `hashKey` folds to a *signed* 32-bit int (`h | 0`), so roughly half of all keys hash negative. `shardFor` used plain `hashKey(key) % shards`, and JS `%` keeps the sign of the dividend — negative keys returned a negative shard index. The range test picks 20 random keys per run, so it failed whenever any of them hashed negative; the fixture test never caught it because every fixture key happens to hash non-negative.

**Fix** (`src/shard.ts:16`): use the non-negative remainder the README and routing table specify, `((hashKey(key) % shards) + shards) % shards`.
