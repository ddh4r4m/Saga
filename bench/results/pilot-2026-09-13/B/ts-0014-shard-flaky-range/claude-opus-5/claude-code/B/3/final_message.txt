The bug was in the code, not the test.

**Diagnosis:** `shardFor` used `hashKey(key) % shards`. JavaScript's `%` keeps the sign of the dividend, so any key whose folded 32-bit FNV-1a hash is negative (about half of all keys) returned a negative shard index. The "live assignments do not move" test never caught it because all 20 fixture keys happen to hash non-negative; the range test generates random keys, so it failed whenever it drew a negative-hashing key — roughly one run in two. The test was asserting exactly the documented contract (README: "the non-negative remainder … the same value Python's `%` gives"), so it stayed untouched.

**Fix** in `src/shard.ts:17`:

```ts
// JS `%` keeps the sign of the dividend, so fold it back into [0, shards).
return ((hashKey(key) % shards) + shards) % shards;
```
