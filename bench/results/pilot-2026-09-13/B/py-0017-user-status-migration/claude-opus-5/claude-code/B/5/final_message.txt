**`app/db.py`** — appended migration 3 (shipped migrations 1 and 2 left alone):

```sql
ALTER TABLE users ADD COLUMN status TEXT NOT NULL DEFAULT 'active'
    CHECK (status IN ('active', 'disabled'))
```

The `DEFAULT 'active'` is what makes both halves of R2 work without touching the loader: existing rows in an already-populated v2 database get `active` when the ALTER runs, and `seed.py`'s unchanged four-column INSERT gets `active` for each seeded row. The `CHECK` is what enforces "and nothing else" — `UPDATE users SET status='pending'` fails at the database.

**`app/users.py`** — `set_status(conn, user_id, status)` validates against `("active", "disabled")` before the UPDATE (raising `ValueError`, so callers get a clear message rather than a CHECK failure) and returns `False` when no such user exists. `list_users(conn, disabled=False)` filters to disabled rows when asked, keeping `ORDER BY id`.

**`app/cli.py`** — added `disable <id>` and `list --disabled`; `format_user` now shows status, and usage text was updated. `disable` on an unknown id prints `no user <id>` and returns 1, matching `show`.
