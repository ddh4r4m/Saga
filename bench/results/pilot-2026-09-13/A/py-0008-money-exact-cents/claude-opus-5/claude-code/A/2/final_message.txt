`Money` now stores an exact integer `cents` field instead of a float `amount`.

**`pricing/money.py`** — `Money` keeps its existing constructor signature, so `Money(0.10)` still means ten cents; the amount is converted once via `Decimal(str(x))` and `ROUND_HALF_UP`, then held as `cents: int`. `__add__`, `__mul__` and `__neg__` are pure integer arithmetic, so nothing drifts and `Money(0.10) * 3 == Money(0.30)` is `True`, including for `hash()`. Added `Money.from_cents()` for exact construction, `as_decimal()` for exact two-place rendering, and kept `.amount` as a float property (`cents / 100`) for the one place that legitimately needs floats.

**`pricing/tax.py`** — rounding is untouched: still `round(subtotal.amount * (1 + rate), 2)` on the float value with the same half-even behavior; `Money` just snaps the result back onto exact cents. I verified parity against the old implementation for every cent value 0–300 plus large/negative values across six rates: zero mismatches.

**`pricing/format.py`** — same output (`$1,234.50`, `-$0.10`, `$0.00`), computed from `divmod` on cents so it can't drift at large magnitudes.

**`pricing/report.py`** — same `name,qty,total` layout, total rendered from the exact decimal.
