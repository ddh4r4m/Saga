You were right that it wasn't the generator. The cause was one stray character in the schema data.

**Root cause:** `schema/order.json` declared `"quantity": { "type": "integer " }` — with a trailing space. The generator doesn't recognize `"integer "` as a known type, so per its design it emitted a validator that rejects everything, and logged a single line amid the wall of output:

```
error: schema/order.json#quantity: unknown type "integer ", emitting a validator that rejects everything
```

That one bad validator cascaded into all 14 failures: 3 direct `order.quantity(...)` checks, plus 11 `order.record` checks that fail because every order record contains a `quantity`. The `fatal:` line's "1 schema errors" was the real signal; the 14 FAILED lines were downstream symptoms.

**Fix:** removed the trailing space in `schema/order.json:12`. That's the only change.

**Verification:**
- `npm run build` → exit 0, `self-check: 63 ok, 0 failed`, `build ok: 41 validators for address, order, product, review, user`
- `npm test` → 1 pass, 0 fail

I checked the other four schema files for the same whitespace pattern in `type` values; `order.json` was the only one affected. The remaining output is all `warn:` lines about missing `description` fields (docs will be empty for those) — pre-existing and non-fatal, so I left them alone.

One thing worth flagging, outside the scope of this fix: an unknown type is treated as a non-fatal error that silently produces a reject-everything validator, which is what buried the signal. Having the generator fail fast on an unknown type — or trim whitespace before matching — would turn a five-minute hunt into an immediate message. Happy to make that change if you want it.
