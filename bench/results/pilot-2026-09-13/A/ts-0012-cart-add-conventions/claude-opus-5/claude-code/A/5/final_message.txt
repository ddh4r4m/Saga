`addItem` now rejects any quantity that isn't a positive whole number, before it mutates the cart.

**Changes**

- `src/commands/add.ts:8-10` — three guards, each naming what was wrong: not a number (`NaN`/`Infinity`), fractional, and zero-or-negative.
- `src/errors.ts:5` — registered `E_BAD_QTY`, required since `fail` throws on an unregistered code.
- `docs/errors.md:8` — the matching table row, per CONTRIBUTING.md rule 2.

Validation goes after the SKU check, so an add with both a bad SKU and a bad quantity still reports the SKU first, as before.
